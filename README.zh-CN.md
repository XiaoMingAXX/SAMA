# SAMA · 土壤分析与植物观测系统

**Soil Analysis and Monitoring Array**
SUTD Innovation by Design 课程中的持续迭代项目。

[English](README.md) · [设计过程](docs/DESIGN.md) · [版本演进](docs/HISTORY.md) · [云端运行](cloud/README.md) · [API](cloud/API.md)

## 我们想解决什么问题

植物养护需要把读数放回具体情境：**测的是哪盆植物、使用哪支传感器、当时是什么状态、之前做过什么养护，以及接下来该检查什么。**

项目从兰花养护出发。项目笔记提到木炭等粗颗粒基质带来的测量困难，以及展陈期间照料不足的情境。这些线索帮助我们定义问题；基质取样方式、传感器准确性和建议效果仍需要实地验证。

我们的工作问题是：怎样帮助兰花种植者判断哪盆植物或哪个区域需要关注，并依据可追溯的记录决定下一步检查？

设计沿着 **Discover → Define → Develop → Deliver** 推进，并随着原型验证反复修正。业余兰花爱好者与小型种植者是目标用户假设；当前不把市场需求、付费意愿或种植效果写成已验证结论。

## 三个阶段

1. **局域网原型 `lan-v1.1.0`**：LOAM Soil Studio，中英双语、模拟观测、真实硬件通信、网关配置与 CSV 导出。
2. **云端演示 `cloud-v0.1.0`**：网关主动连接服务器，集中查看实时读数及近期历史。
3. **数据仓库 `cloud-v0.2.0`**：独立账号、管理员全局管理、植物档案、养护事件、传感器轮用、按段采集、照片、历史回看与数据下载。

这三个阶段由现存源码快照重建为公开提交和标签。提交时间是整理发布的时间，没有伪造原始开发日期。

## 新版围绕植物保留记录

- 用户自行注册，管理员也可建号、重置密码、分配设备；普通账号只管理自己的植物、记录与照片。
- 传感器与植物分开建模。同一支传感器可依次测不同植物，也可由管理员转交给其他账号；历史保留当时的归属和绑定。
- 实时显示与长期保存分开。可以手动存一条、开始/停止一段记录，或设置起止时间。保存间隔、稳定等待和保留全部成功读数均按段配置。
- 上传植物档案照、日常状态照，或给某次采样补照片；填写生长阶段、浇水、施肥、换盆等事件。目前没有自动拍摄。
- SQLite 保存账号、档案、绑定和近期读数；私有 OSS 保存历史分块、照片、导出和备份。支持 CSV、NDJSON、ZIP 下载。
- 生成 `sama.plant-context.v1` 固定版本数据快照，为未来的大模型分析提供单位、来源、时间范围和数据限制。当前尚未调用模型生成建议，也不自动控制养护。

## 本地体验

安装 Node.js **24.15+**，其 SQLite 需为 **3.51.3+**。在仓库根目录执行：

```sh
npm ci --prefix cloud --include=optional --ignore-scripts
cd cloud
node manage.mjs demo
node server.mjs
```

打开 `http://127.0.0.1:3180`。首次演示初始化要求空工作区；随机生成的账号密码保存在 `cloud/data-v2/preview-credentials.txt`。本地数据与对象文件均不会提交到 Git，不需要 OSS 或真实硬件。

Windows 也可使用 `cloud/start-local.ps1 -InitDemo` 启动独立预览。完整说明见 [cloud/README.md](cloud/README.md)。旧局域网版本在根目录执行 `npm start`，访问 `http://localhost:3000`。

根目录 `npm test` 验证 LAN 的 18 项测试，`npm --prefix cloud test` 验证仓库的 9 项集成测试。测试覆盖权限隔离、转交、照片、归档、导出和故障恢复，不代表测量准确性或真实种植效果已经验收。

下一步需要验证实物网关、兰花基质中的测量与校准、预期规模下的持续运行，再接入可由用户核验的分析建议。正式部署准备见 [部署说明](docs/DEPLOYMENT.md)。
